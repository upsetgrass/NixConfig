# Git 操作授权规则

在任何 Pi 会话中，除非用户在自己的提示词中**明确要求执行具体的 Git 写操作**，否则不要执行任何会修改仓库、索引、分支、工作树、历史、标签、远端或托管平台状态的 Git 相关操作。包括但不限于 `git add/commit/push/fetch/pull/merge/rebase/reset/checkout/switch/stash/clean/tag/worktree`、修改式 `git config`，以及通过脚本、其他工具或 API 间接完成相同操作。只读的 `git status/diff/log/show` 等检查可以执行。

“修复代码”“完成任务”“按 ub-mode 做”“处理 Git”等笼统请求不是 Git 写入授权。授权只覆盖明确要求的具体操作：请求提交不等于允许推送，请求推送也不等于允许推送到主线。用户只询问如何操作时，可以给出建议和示例命令，**不要执行**。有歧义就先询问用户；没有授权时报告现状和建议步骤，保留未提交工作。

本文件是行为约束，不是 OS 级权限隔离；不要把它误称为硬性沙箱。
